# BTC Analyst: notes for Claude

Read this first. It carries decisions and context from earlier sessions that are not obvious from the code. Keep it up to date: when a session makes a decision the owner will care about later, add it here in the same PR.

## The owner

- Based in the UK, buys Bitcoin in pounds on Coinbase, and is not a trader. Explain things in plain English, not trader jargon.
- Write UK English, and no em dashes, in chat replies and in text written into the app.
- Uses the app as an installed Android APK, not Expo Go.

## What the app is

A rules-based Bitcoin dashboard and allocation advisor: React Native + Expo (SDK 54), TypeScript, expo-router. No backend, no accounts, no API keys. The README explains the signal engine in depth.

Tabs: Home, Chart, Signals, Portfolio, Market, Settings. The first tab is labelled "Home" because six tabs cut "Dashboard" off. Market was called On-Chain (file still `app/tabs/onchain.tsx`, test ID `tab-onchain`): it holds Fear & Greed, market size and network health, and Fear & Greed is mood, not on-chain data. Paper trading is inside the Portfolio tab, not a seventh tab.

## Layout and conventions

- `src/services/`: pure logic, no React or React Native imports, so it can be tested directly. Put new logic here and test it. The one exception is `api.ts`, which adds the web-only rule on top of `marketApi.ts`.
- `src/hooks/`, `src/context/`: thin React wrappers. `src/components/`: shared UI.
- `__tests__/`: Node's built-in test runner. The tests need no dependencies (though Yarn itself wants `yarn install` first on a fresh clone; see below). `yarn typecheck` needs dependencies.
- Glossary text for the (i) buttons lives in `src/services/glossary.ts`. Every Signals reading carries a `plain` line and a `term` pointing at a glossary entry, and a test enforces both.

## Snapshot and /btc-brief

- `yarn snapshot` (or, with nothing installed, `node --experimental-strip-types --no-warnings --import ./backtest/register.mjs scripts/snapshot.ts`) prints the app's full reading from live data as plain text: UK time, price in USD and GBP, Fear & Greed, every indicator, each signal layer with the rule and threshold behind it, the overall advice, other timeframes and on-chain. Options: `--timeframe 1H|4H|1D|1W`, `--stretch-weight`, `--currency`. Exit code 1 when the price or the signal timeframe's candles failed; the report still prints what loaded.
- It must never calculate anything itself. `scripts/snapshot.ts` fetches through `src/services/marketApi.ts` (the app's fetchers, split out of `api.ts` so Node can import them without React Native) and `src/services/marketReport.ts` runs the app's own `dropIncompleteCandle`, `computeIndicators`, `computeSignal` and `describeMarket`. Thresholds it prints come from constants the engine exports (`STRETCH_RANGES`, `MOMENTUM_RANGES`, `ACTION_TIERS`, `READING_DEADBAND`), and the allocation breakdown from `SignalResult.allocationParts`. If you change a threshold in the engine, change it there, not in the report.
- It cannot read the phone's settings. Defaults match the app's defaults; pass flags if the owner has changed theirs.
- **The app can export the same report:** Settings > Share with Claude > Share snapshot (`src/components/SnapshotShareCard.tsx`). It fetches fresh data on the phone, with the phone's settings, and opens the share sheet with the text; the owner pastes it under `/btc-brief`. This exists because cloud sessions often cannot reach the data sources, and it is the most faithful copy of what the app shows. The phone export and the script both go through `collectSnapshot` in `marketReport.ts`, so they cannot drift apart. Text was chosen over screenshots or a zip: it carries every number exactly, pastes reliably into a Claude chat, and needs no new native modules. The status line under the button names any failed source with its reason, which should also finally show why Fear & Greed fails on the owner's phone.
- No source needs an API key. If one is ever added, read it from an environment variable (`.env` is git-ignored) and never commit it.
- Claude Code cloud sessions block all four data hosts by default (HTTP 403 from the egress proxy). To run the snapshot there, add `api.kraken.com`, `api.alternative.me`, `api.coinpaprika.com` and `mempool.space` to the environment's allowed domains (environment menu in the session title bar, Edit, Network access). It works anywhere else with ordinary internet access.
- `/btc-brief` ends with a one-line "Paper log" (verdict, confidence, the three chances, limit orders with a 1, 2, 7 or 14-day expiry) for copying into a paper decision, and states its chances as "lower than now at that moment", which is how the paper record scores them.
- `.claude/commands/btc-brief.md` is the owner's `/btc-brief [amount in GBP]` command: it uses a snapshot pasted from the app if there is one (checking its age against the current price), otherwise runs the snapshot, researches news, macro, ETF flows, derivatives and scheduled events, then gives a short-term call (verdict, entry, split and limit orders, probabilities, levels, invalidation, confidence). The owner asked for it to be direct and without disclaimers. It is a separate short-term view, and does not change the app's own stance that its signal is a long-term allocation, not a prediction.

## Checks before pushing

1. `yarn typecheck` and `yarn test`. CI installs with `--immutable`, so after any dependency change run `yarn install` and commit `yarn.lock` (`.yarn/install-state.gz` is git-ignored). In a cloud session Corepack cannot download Yarn from repo.yarnpkg.com; prefix commands with `COREPACK_NPM_REGISTRY=https://registry.npmjs.org` and it fetches Yarn from npm instead. On a fresh clone Yarn also refuses to run any script, `yarn test` included, until `yarn install` has run.
2. `yarn expo export --platform android` (the same bundling step CI runs; it catches missing modules that typecheck misses).
3. For UI changes: export the web build and drive it with Playwright at phone width (about 400px). The cloud sandbox cannot reach Kraken, CoinPaprika or Alternative.me, so intercept those requests and answer them with synthetic candles and prices. Chromium is at `/opt/pw-browsers`.

## Delivery

- Work on a branch and open a PR into `main`. The PR description is the record of what changed and why, for future sessions.
- CI (`.github/workflows/ci.yml`) runs typecheck, the Android bundle, tests, a live probe of every data source (informational only) and a backtest smoke test.
- The APK workflow builds on every push to `main` or `claude/**` and republishes the same link: https://github.com/tahae02/btc-dashboard/releases/download/apk-latest/btc-analyst.apk. It takes about 11 minutes. Installing over the top keeps the owner's data; uninstalling wipes it.

## Decisions already made (and why)

- **The engine does not retune itself from results or from the owner's trades.** Two years of daily data holds fewer than two dozen independent months, and a month's BTC move is routinely ±20%, so self-tuning would fit noise. The owner accepted this. Parameter changes go through `yarn backtest --split` on real data instead. The Track record (Signals tab) is how to spot when that is worth doing.
- **The signal is an allocation for a long-term buyer, not a price prediction.** The 24h and 7d "ranges" are volatility bands (ATR-based), not forecasts. Do not describe them as predictions.
- **Every trade records the full picture at that moment and never recomputes it:** advice, regime and score, conviction, target allocation, DCA multiplier, Fear & Greed value and label, RSI, volatility, the 200-day average and the distance from it, stretch, momentum, and the market price in both GBP and USD. Back-dated trades get this replayed from history (with that day's Fear & Greed from its full history) and are marked "replayed". The owner wants this kept for looking back later, so do not drop fields.
- **Starting balance:** a snapshot of what the owner already held (total put in and BTC held). Trades dated at or before it are already inside it and are not added to holdings again. That lets old orders be back-logged for signal tracking without double counting.
- **Trade entry mirrors Coinbase order details:** total, fee, BTC and price per BTC. Any two of total, BTC and price give the third. All three are cross-checked. Buy: total = BTC x price + fee. Sell: total = BTC x price - fee.
- **The Portfolio tab always shows GBP and USD, whatever the currency setting.** Holdings value and P&L sit side by side; cost of holdings, average cost, realised and total put in show GBP with USD underneath. Each trade is converted into the other currency at the rate on its own day, implied by its recorded `marketPriceGbp / marketPriceUsd` (`convertAtTrade` in `journal.ts`). Only the starting balance (no single day) and a trade missing either price use today's rate; `HoldingsSummary.atTodaysRate` flags it and the screen says so. This changed in November 2026: the review found dollar costs used today's rate although every trade stores both prices.
- **Data loads progressively.** Each source's result is shown as it arrives, and the last good data is shown instantly on launch. Do not go back to waiting for every source before rendering; that caused a 20-second blank screen.
- **A trade's "What happened next" shows money next to each percentage**, e.g. "+1.5% (+£50)". The money is the move applied to the BTC from that trade, valued at the price paid (total minus fee on a buy), so it always has the same sign as the percentage. The percentages stay BTC/USD market moves, as before. A final row, "Worth now, vs what you paid", gives the real difference today with the fee included, which can be lower. Logic is `moveInMoney` and `worthNow` in `journal.ts`.
- **"What if Bitcoin hits…" calculator** lives on the Portfolio tab, below the buy and sell buttons, not in a new tab (six tabs already cut labels). The owner asked for a price slider, dollars by default with a switch to pounds, and the result as money and a percentage. "My Bitcoin" values the BTC held against the cost of holdings (GBP); "An amount" assumes a buy at today's price before fees. Results always show pounds and dollars, converted at today's rate. The slider is a log scale from 10k to 1M, built on PanResponder so it needs no native module. Its choices are remembered under `btc_dashboard_calculator_v1`. It is arithmetic, not a forecast, and the card says so. Logic is in `src/services/calculator.ts`.
- **Paper trading** sits on the Portfolio tab behind a *My trades* / *Paper* switch (the last choice is remembered under `btc_dashboard_portfolio_view_v1`), because the owner asked for it near real logging but slightly separate. It never mixes with real data: its own keys (`btc_dashboard_paper_v1`, `btc_dashboard_paper_settings_v1`), its own backup (`kind: 'paper'`, trades under `paperTrades`, never `trades`) and CSV. The real journal's parser refuses any record carrying a `paper` field, and the paper restore refuses a real backup. Logic: `src/services/paper.ts` (model, storage, fills, recorded outcomes, CSV) and `src/services/paperReview.ts` (scorecard); state and background checks in `src/context/PaperTradingContext.tsx`; screen in `src/components/PaperPortfolio.tsx`.
- **Paper decisions are always at the live price, never back-dated**: a paper trade logged afterwards would be chosen with hindsight. Three kinds: a trade (buy or sell), a limit buy, and "don't buy". The sheet fills in the app's amount (usual amount x DCA multiplier) so following the advice is the easy path. The app never advises selling, so a paper sell has no app amount.
- **Every paper decision records what a real trade records** (the full `SignalStamp`, market price in GBP and USD) **plus**: whose call (app, Claude's brief, own), why now (scenario), usual amount, the app's amount, the BTC/USD 24-hour change, and for a brief its verdict, confidence and chances of a lower price after 24 hours, 48 hours and 7 days. The price 24h, 48h, 7d, 30d and 90d after each decision is recorded once due, from fresh hourly bars (a daily bar only once it has closed), and never recomputed, so outcomes stay hour-accurate after the 30 days of hourly history roll on. Do not drop fields.
- **Paper limit orders** fill from hourly candles in the order's currency (GBP candles are fetched for that), counting only whole bars that start after placing and end by the expiry, at the limit price, with the limit fee. That can miss a dip in the first or last hour but never invents a fill. The live price also fills an order while the app is open. Expiry is 1, 2, 7 or 14 days so the window always sits inside the hourly history; an order the app could no longer check (not opened for weeks) is marked "could not be checked", not guessed. A filled order and its trade are one decision: deleting either removes both.
- **Paper fees** default to Coinbase Advanced's entry tier (1.2% taker for buying now, 0.6% maker for a limit order, checked in October 2026) and are editable; the settings card shows the average fee the owner's real buys paid.
- **The paper scorecard** ("How the advice has done"): paper buys against the same money spread evenly over the same UTC days (filled limits count on the day placed, at the limit; "don't buy" days count; unfilled orders do not; before fees), outcome groups by whose call / why / tier / against the app's amount, a Brier score for Claude's chances against 0.250, verdict outcomes, limit order stats, and real against paper average price per BTC since paper trading began. Thresholds: 5 buys per group, 8 days, 20 calls; below them it says "too few to judge". Like the Track record, it is never used to retune the engine.
- **When and how often to paper trade** is set out in the app (`src/components/PaperGuideCard.tsx`): every regular buy day without fail (the backbone that keeps the record unbiased), extras when the advice changes, Bitcoin moves 5% in a day or 10% in a week, Fear & Greed is at 20 or below or 80 or above, or a big event is due (at most one extra a day), and whenever the owner is tempted to trade for real. Review monthly on the card, quarterly with `/paper-review`.
- **`/paper-review`** (`.claude/commands/paper-review.md`) takes the paper backup or CSV. `yarn paper-review <backup.json>` prints the app's own scorecard from a backup with no network; the command builds on it. It may propose edits to `/btc-brief` (a prompt) once there are 20+ scored calls, but engine changes still go through `yarn backtest --split`.
- **Pounds by default (November 2026).** `DEFAULT_SETTINGS.currency` is GBP. Settings saved before then carry the old USD default whether or not it was chosen (the whole object is saved on any change), so `applyPoundDefault` moves a stored USD to GBP once, marked by `btc_dashboard_gbp_default_v1`; after that a USD choice sticks. The price currency now drives the headline, Home figures, Signals levels, Market sizes and the Chart (Kraken's own BTC/GBP candles). The advice is still always computed on BTC/USD, and RSI and MACD on the Chart come from BTC/USD so they match Signals.
- **Trade forms never take their currency from the display setting.** Log a buy/sell and the starting balance open on the currency of the most recently logged trade (or the starting balance), else GBP (`tradeDefaults`). That stops a £500 Coinbase buy being saved as $500. The fee is not prefilled; a one-tap "use your last fee rate" appears once a total is typed.
- **The candle chart is drawn by the app (`src/components/CandleChart.tsx`, geometry in `src/services/chartWindow.ts`), not by react-native-gifted-charts**, which was removed. gifted-charts-core 0.1.82 coloured a candle "bullish" when it opened above its close, so rises were red. `candleIsUp` (close >= open) is the one rule, with a regression test. The window stays a screen's width of candles (Android bitmap limit); dragging moves it through history, never widens it. Price labels land on round steps (`priceScale`). SMA 200 is the default line; Bollinger is one choice that draws both bands. Your real trades are dots at what you paid per BTC with fees (`tradePricePerBtc`) and a dashed line at your average cost.
- **Fear & Greed gauge:** a reading never spans more than half a circle, so SVG's large-arc flag is always 0 (`src/services/gauge.ts`, tested). It flipped to 1 above 50 before, which drew the arc off the picture.
- **Support and resistance wording** comes from `levelDistance` in `src/services/levels.ts`, used by Signals, the engine's reading text and the snapshot. A level the live price has already gone through says "already broken: the price is X% under it", never "-0.9% below".
- **Text colours and numbers:** `textSecondary` #A0A0B8 and `textTertiary` #80809A both pass 4.5:1 on the card background (the faintest was 2.6:1). Figures use the normal font with tabular digits (`Numbers` in `theme.ts`), not monospace; `Fonts.mono` is only for pasted backup text. Charts are react-native-svg; give every `SvgText` `fontFamily={Fonts.system}` or web renders it in a serif.
- **Home shows the advice headline only** (badge, plain line, allocation bar, DCA line); regime score, conviction and readings are on Signals. Fear & Greed is a chip on Home that opens Market, where the dial and 30-day chart live. The *Worth a look today* card (`HomeAlertCard`) reuses paper's `detectConditions` (advice changed, 5% day or 10% week, Fear & Greed <= 20 or >= 80) and is dismissed until the conditions change. It is in-app only.
- **Signals:** the five reading groups fold to one line each until tapped. `useTrackRecord` runs once on the Signals screen and is passed to both `TrackRecordCard` (which has a last-12-months / all switch) and `AdviceHistoryStrip` (a year of replayed advice as colour bands under the price, `adviceRuns`). Do not call the hook in two places: each instance would replay the history again.
- **Portfolio additions:** a daily "worth against what you paid" chart in pounds (`portfolioHistory`, from Kraken's GBP daily closes; it starts at the starting balance or first trade); trade list filters (side, advice then, year); a UK tax-year gains card (`src/services/ukTax.ts`: same day, then the next 30 days, then the section 104 pool; fees in costs; dollar trades at the day's rate; the starting balance is the opening pool; allowance table up to 2026 to 2027, later years marked assumed). It is an estimate and says so. **Import from Coinbase** (`src/services/coinbaseImport.ts`, `CoinbaseImportSheet`): pasted CSV text, columns found by name so both the old and new Coinbase layouts work, BTC buys and sells in GBP or USD only; each becomes a back-dated trade with both market prices and a replayed stamp, ID `cb-<Coinbase ID>` so a second import adds nothing, and hand-logged duplicates (same side, within 2 minutes, BTC within 0.5%) are left out. Paste rather than a file picker because a picker needs a new native module.
- **Paper:** the guide is three picture cards (when, how, how long) with the full text one tap away, and sits under the buttons until the first decision. `RealVsPaperChart` draws real and paper average price per BTC since paper trading began (`avgPaidSeries`).
- **Not built from the November 2026 review, on purpose:** push alerts and a buy-day reminder (need expo-notifications and background tasks), a home-screen widget (native Android code), fingerprint lock (expo-local-authentication), automatic backup to a file (needs a storage-access native module), and sharing buys with the Life Admin app (a different app). Each needs a new native module and a new APK, so they were left for a separate change. Folding Market into another tab to get five tabs was not done either: Home and Signals are already long, so the tab was renamed and the labels made larger and brighter instead.
- Old trades, backups (v1 and v2) and settings must keep loading after any change. Storage parsers validate field by field and default missing fields. The same goes for the paper record and its backup (version 1).
